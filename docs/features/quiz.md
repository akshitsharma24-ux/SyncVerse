# Quiz arena

Timed DSA quizzes for a room: a mentor creates one in five short choices, students answer it live, and everyone watches a leaderboard.
It is the **Quiz** tool in the learning panel; while a quiz runs there is also a **Quiz live** chip in the top bar.

![The quiz in progress](../images/quiz-arena.png)

## How a quiz goes

1. **Create.** The mentor (owner or mentor role) answers five questions: **topics** (arrays, strings, hash maps, stacks and queues,
   binary search and sorting, recursion and backtracking, dynamic programming, graphs and grids), **difficulty** (LeetCode's Easy,
   Medium, Hard, or a Mixed ramp from easy to hard), **type of question** (multiple choice, coding, or both), **how many questions**
   (2 to 10) and **how much time** (3 to 180 minutes). One switch decides whether students may watch the leaderboard while it runs.
2. **Lobby.** The mentor sees the chosen questions and can reshuffle them. Students only see how many questions there will be.
3. **Run.** The mentor presses Start. Students answer in a full-window view with a countdown that follows the server's clock.
   - *Multiple choice:* one try, instant "correct / not this time", the right answer stays hidden until the end.
   - *Coding problems:* a private Monaco editor (nothing is shared) in Python, Java, JavaScript, C++ or C. **Run** tries the program on any
     input; **Submit** judges it on every test (the samples plus hidden tests) in the same sandbox as the console's Run button. The
     student sees which sample failed and what was expected, never the hidden tests. The best submission counts.
4. **Score.** 10 / 20 / 30 points for Easy / Medium / Hard. A coding answer pays by the share of tests passed, and full marks only when
   every test passes. Ties go to whoever reached the score first.
5. **End.** Time runs out, or the mentor ends it. Answers close; everyone gets the **final leaderboard with a podium**, the right
   answers with explanations and a model solution for each coding problem. The mentor can **export a CSV**. Finished quizzes stay in
   the room's history.

![Final leaderboard](../images/quiz-board.png)

The mentor sees, live: who has started, a leaderboard with each question marked solved / partly right / tried / not tried, and how each
question went for the class (how many solved it, how many tried). The leaderboard opens as a full-window board to share on screen.

## The question bank

88 questions in `server/quiz/`: **48 multiple choice** (two easy, two medium, two hard per topic) and **40 coding problems** (LeetCode
style, over the same eight topics and three levels). Coding problems read standard input and print the answer, so they work in every
language. Answers and hidden tests never leave the server.

- The expected output of every hidden test is **generated by running the problem's model solution** (`npm run gen:quiz`), and each problem's
  hand-written samples cross-check that solution, so a mistake in a model solution stops the generator.
- `npm run verify:quiz` checks the bank: counts per topic and level, well-formed questions, the right answers spread evenly over A to D,
  at least five tests per problem, and that the generated outputs are up to date.

## API (all under `/api/quiz`, room named by the `x-room` header)

| Route | Who | What |
|---|---|---|
| `GET /catalog` | anyone | topics with how many questions each level has, and the languages the runner supports |
| `GET /` | members | the room's quiz as this person may see it |
| `GET /stream` | members | server-sent events: the same snapshot, pushed whenever anything changes |
| `POST /create`, `/reroll`, `/start`, `/end`, `/cancel` | mentor | run the quiz |
| `POST /answer` | student | `{ questionId, choice }`, one try |
| `POST /run` | student | try a program on any input (no score) |
| `POST /submit` | student | judge a coding answer on every test; one at a time per person |

Quizzes are saved to `server/data/quizzes.json`, so a server restart does not lose a running quiz. Code: `shared/quiz.ts`,
`server/quiz/`, `server/routes/quiz.ts`, `web/src/quiz/`.

## Tests

`npm run test:quiz` (API: create, start, answer, judge, live leaderboard, end, permissions, persistence), `npm run test:quiz:languages`
(Java, JavaScript, C and C++ judged through the real runner, needs internet), `npm run verify:quiz` (the bank) and `npm run e2e:quiz`
(browsers: mentor, three students and a viewer, both question types, live board, podium, CSV, phone layout, accessibility).
